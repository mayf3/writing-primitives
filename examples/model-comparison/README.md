# 跨模型写作样例：固定材料、保留原稿、比较取舍

**状态：样例采集协议 / 尚未运行。** 目前仓库**没有真实 Gemini 输出**，也没有可以据此宣称 Gemini、GPT 或某种 Writing IR 更好的测评成绩。请勿将本仓库的自编示例误标为 Gemini。

本目录供将来积累经过许可、可公开的**真实模型产出**，比较不同写作模型及不同修改流程的表现。研究重点不是“谁的金句更漂亮”，而是**谁在保持 D/C/R 的同时，让 U 适合具体读者、媒介和说话人**。

## 固定任务

见 [BRIEFS](BRIEFS.md)：每个任务均有原创虚构的事实包、作者契约与篇幅要求。优先收集三种体裁：非虚构短文、面向普通人的对谈、通俗技术解释。

每份真实输出应记录：

- 输入包的 ID、版本、完整 prompt 与语言；
- 模型服务商、**准确模型 ID**、客户端与版本、日期、温度等已知设置；
- 是否调用外部工具、是否使用系统预设、是否可访问私有文件；未知项写 `unknown`；
- **原始未修改输出**（raw）、后编辑候选、编辑人/Agent 的改动差异；
- 该稿 C.scope / modality / attribution / R 是否保持；改变的具体位置；
- 真人朗读/盲法评价的原始记录（如确实执行），否则注明 `not_tested`；
- 模型输出的公开使用许可和样例是否完全合成、不会泄露个人内容。

**不能“先选表现好的句子，然后把那些句子当基准”**：这会产生选择偏差。即使作者觉得某个模型“更有人味”，也应保留失败稿及自然但事实越界的反例。

## 建议的采样设计

对每个 BRIEF 比较：

A. 模型直接按“面向目标受众写一篇好文章”的强普通提示词生成；

B. 同一模型使用明确 D 与事实包生成，再运行 Light IR 审核；

C. 在 B 的稿件上，按需执行 `natural-chinese-voice` Voice Pass，同时保持 C/R 不变。

如果要跨模型比较，同题目、同样提示词、预算与样例选择规则；不要让某个模型额外拿到其他模型没有的上下文或无限修订次数。**原始稿与 Voice Pass 的对比不等于模型间公平排名**，应分别记录。

## 怎样判断效果

分开看：事实/来源边界、作者意图、局部表达、真正的对话回应、朗读是否顺畅、真实受众理解、作者修改时间与成本。允许多个表达版本同时合格。

机器可用词汇密度、句长与格式统计辅助寻找问题，但不能让统计代替作者或目标读者。对口播/对谈，实际听音频的反馈比只看书面文本更有意义。
