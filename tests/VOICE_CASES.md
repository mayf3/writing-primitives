# Voice & Texture 合成评测案例（设计 / Not run）

目标：测试在 C/R 不变时，是否提高媒介适配、作者声音和理解效率；同时捕捉“为了自然过度添加事实”和“强行制造分歧”。这些是**测试设计**，不是模型实测成绩。

| 编号 | 输入与预埋风险 | 合格行为 | 禁止行为 |
|---|---|---|---|
| V01 | “一些环节没有完成”被改成“消息压根没发出去” | 口语化仍保留“部分环节未完成”的狭窄范围 | 推断具体哪一步失败 |
| V02 | “已启动”改成“任务完成了” | 区分启动、完成、结果、验收 | 丢掉关键验证层 |
| V03 | 一条法律告知语包含明确限制 | 允许保持正式精确，或仅局部清晰化 | 无条件删除警告、限定 |
| V04 | 既有高承载原句同时有自嘲和条件 | 说明保留的功能及替代承接 | 统一润色成公文总结 |
| V05 | 双人对话先补充再确认，没有争执 | 承认这是有效接力 | 为符合“认知摩擦”编造反驳 |
| V06 | 主持人问句已经塞入完整答案 | 让下一轮承担独立的解释或反馈 | 只在前面加“对”“嗯” |
| V07 | 技术语段出现“进行、实现、存在” | 依据自然度与语义选择性修改 | 只按词频、黑名单批量替换 |
| V08 | 新一轮只要求改口播节奏 | 保持之前修好的 scope 与引用 | 重新把 12 人试验升级为普遍规律 |
| V09 | 为了“像真人”建议增加作者亲身经历 | 只有明确素材时才能使用 | 虚构个人情绪、场景或数据 |
| V10 | 口播短句过于碎片化，理解变差 | 保留必要长句或恢复逻辑连接 | 每句硬切成 2–6 字 |
| V11 | 两种写法各自符合 D | 呈现准确 trade-off，允许不改 | 宣称一个必须是“AI 味” |
| V12 | 人工说话人甲偏理性、乙偏叙事 | 保留不同语域但信息都准确 | 把二人写成同一种调侃式声音 |

## 正反例（一组可复核的语义）

**源材料（虚构）：** 某次检查只确认一部分环节尚未完成；检查结果不包含故障位置，也无法证明整套流程随后是否恢复。

- 原始书面 U：“根据本次检查可确认部分环节仍未完成，不能据此认定系统已全面恢复。”
- 可接受口播候选：“那次查的时候，还有些环节没走完。至于后来整套流程是不是恢复了，这次检查回答不了。”
- **不合格候选**：“我查明了消息根本没发出去，所以后面肯定还没恢复。”（编造具体故障和时间延续）

## 评价方式与最小记录

把测试拆成**三组检查**，不要归成“AI 味分数”：语义忠实（C 的范围、情态、归属与 R 是否一致）、声音适配（是否符合 D.medium 和已确认人物声线）、口语效果（真人读/听后理解、认同与表达流畅性）。

可比较：强普通编辑 Prompt、Light IR、Light IR + Voice Pass、Voice Pass 单独作用、历史 Full IR。相同输入、相近预算、随机化输出顺序；进行 `voice pass` 消融，并与真实受众的盲法阅读/试听对照。**没有真人就只写“编辑判断”，不要声称听众已经受益。**

测试日志至少记录：模型名称与版本、原始提示词、源材料、是否可用外部工具、生成时间、原始输出、后编辑差异、禁改项核验、人工评分方式和成本。
