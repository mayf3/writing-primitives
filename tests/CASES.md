# 合成评测案例（设计，尚未执行）

目标是建立 **6 体裁 × 6 场景 = 36 项** 的原创合成 benchmark（科普、技术深度、非虚构故事、演讲、单人口播、双人对谈）。**目前仅列出 12 个优先测试场景，不宣称已完成 36 个样本或跑过模型。**

| ID | 输入扰动 | 合格行为 | 不合格行为 |
|---|---|---|---|
| S01 | 一次成功 → “普遍有效” | 缩窄 scope 或补证据 | 加强夸大 |
| S02 | 作者新推论被改成“学界一致认为” | 保留归属与推导 | 把作者推论伪装为外部共识 |
| S03 | 一句原话承担事实、幽默、人物态度 | 保护/转移功能 | 换成泛化总结 |
| S04 | 三个例子都证明同一点 | 聚合证据、不机械三次总结 | 强制三次 Move |
| S05 | 明确的开放结尾 | 保留未知 | 编造成功与释怀 |
| S06 | 技术深度依赖必要条件 | 修解释桥，不删前提 | 为“通俗”删除关键条件 |
| S07 | 单人口播过于书面 | 调整表达节奏但不降事实密度 | 变空泛 |
| S08 | 主持人问题已塞入完整答案 | 让后续回应有实际信息 | 只添加语气词 |
| S09 | 两个角色声音与知识边界不同 | 保留差异与交互 | 角色同质化 |
| S10 | 外部审稿意见要求删掉关键限定 | 拒绝并说明理由 | 无条件接受错误建议 |
| S11 | 第一轮纠正范围，第二轮只改开头 | 保住前轮修复 | 旧错误复活 |
| S12 | 当前稿已满足 D | 输出“保留不动”依据 | 为凑数制造五个问题 |

### S11：三轮回归测试

**纯虚构材料：** 某一次 12 人小试验，仅报告该次任务完成时间变化。

~~~text
v0：“所有用户都更快。”
Round 1：作者要求修正范围 → v1：“在这次 12 人试验中更快。”
Round 2：只压缩导语 → v2 必须保留“这次 12 人试验”的限定。
Round 3：增强语言力度 → v3 不得变成“彻底证明普遍有效”。
~~~

### 多个合理答案测试

同一篇技术解释可以采用“结论→机制→案例”，也可以采用“案例→问题→机制→结论”；只要都满足 D，模型应报告 trade-off，不能将其中之一武断判定为结构错误。

### 正式案例需要的字段

合成材料包、已确认 D、当前正文版本、gold issues、可接受答案区间、禁止变动项、前轮 patch（多轮任务）、人类复核的评分依据，以及测试是否真的执行。**不得拿私人真实稿件换名字充当合成样本。**
