# 历史使用经验（匿名抽象；非实证结果）

本页将过去写作与审稿中的经验抽象成**通用编辑问题**。原始私人稿件、人物经历、工作信息和对话均不进入 public。以下属于 [经验]，不是系统效果的受控实验，也不意味着案例事实经过独立核验。

| 典型场景 | 易发生的问题 | 值得保留的检查 |
|---|---|---|
| 经验汇报/技术演讲 | 材料越补越多，真实行动/反馈被宏观总结淹没 | 新事实是填补 R 缺桥，还是只让清单更长？ |
| 深度技术长文 | 为可读性删去条件和原创推导 | 区分外部观点、亲身观察、作者推论；先修关系再改措辞 |
| 非虚构故事 | 为戏剧性虚构预期、内心、反转和完满结局 | 只保留有来源的目标、行动、反馈、同维度变化 |
| 双人/多人对谈 | 变成轮流读独白、问题抢答、角色口吻同质 | 下一轮是否回应、纠正、追问或带来新信息？ |
| 多轮改稿 | 新意见反复推翻已稳定内容，旧诊断未更新 | 回到最新版、检查前轮守卫、明确停止 |

## 五个“不等于”

1. **材料更多 ≠ 读者理解推进更多**：三个例子可能只服务同一个观点，不能机械拆成三个 Move。
2. **句子更顺 ≠ 更像作者**：高承载原句同时表达事实、玩笑、犹疑、人物声音或前后呼应；润色前要列出保护项。
3. **加口头语 ≠ 形成真实对话**：问答的相互条件关系比“嗯、对、然后”更重要。
4. **建议被采用 ≠ 实际落实和验证**：必须查当前稿、diff 与被影响的关系。
5. **看起来圆满 ≠ 合适的结尾**：允许真实开放结果、复杂感受及多个合理表达顺序。

## 对旧使用方式的修正

旧体系有长期价值的原则：planned/observed 分开；事实与人物自述有来源状态；高承载表达不因“不书面”被抹平；RS 的编辑预测不可冒充实测；每次修改要比较增益和损失。

潜在负担则包括：小修改也强制填七类表；每段必须说明读者“升级”；不断细分 Relation 词表；每轮以大量问题显示专业性。vNext 把重心转向**少量可举证问题 + 最小 patch + 回归 + 停止**，必要时才展开事件/Move/Reader Evidence。

中文书面、口播、真人对谈应分别评估。没有对照研究证明新方法优于强普通编辑提示词，必须允许失败与进一步删减。
