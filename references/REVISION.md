# Revision Protocol · 少量问题、具体候选、必要回查

Revision 是修改协议，不增加核心原语。日常任务不必输出本页字段；用它说明复杂修改的依据与代价。

## 1. 从当前版本和任务出发

审稿先恢复 observed，再对照作者确认的 D 与材料，按影响、依据和改动风险选少量关键问题，不计算伪精确总分。

| 分类 | 判断依据 | 动作 |
|---|---|---|
| must_fix | 事实或关系错误，或 D 要求的内容确实缺失 | 指明原句/缺口并修补；缺材料不硬编 |
| optional_experiment | 有具体改进理由，但存在多个合理方案或效果待比较 | 给可逆候选，说明取舍 |
| leave_alone | 满足当前任务且无实质问题，或不在本次改动范围 | 保留 |

受众可能不在意、跟不上，属于有待检验的编辑判断；文本矛盾和已确认目标的内容缺口，可以直接依据材料指出。叙事、陪伴与审美按其自身 D 评价，不强加教学清单，也不整体免检。

## 2. 最小有效修改与可选试写

最小有效修改按问题是否解决、语义风险、非目标变动、功能损失和作者返工比较，不按字数或 U → R → C → D 的层级试错。改一个限定词可能比移动一段更危险。可重排 Move、补有依据的 R/C；更改 D 仍由作者采用。

作者希望探索时，可保留原方向的可用版本，并在最能展示差异的位置试写一个备选。这有时可称“守与探”，但不是必须两版的配额，也不限定开头、字数或只在材料闲置时启用。仅需改一句或终稿校对时，不额外重开方向。作者未回应不算采用，也不永久禁止以后探索；本轮不重复推销。例见 [SMALL_PROBE_AND_NARRATIVE](../examples/SMALL_PROBE_AND_NARRATIVE.md)。

复杂 patch 可用下面的轻量记录；简单改句直接给前后对照：

~~~yaml
base_version: draft-v2
anchor: 第3段 / 准确原句
issue: 把一次试验外推成所有场景
operation: replace # 也可 insert / delete / move / split / merge
candidate_after: 在这次试验里，参与者完成任务的时间更短。
preservation_guards: [仅限本次试验, 保留来源与归属, 保留后文限定]
expected_gain: 消除范围外推
possible_losses: [结论力度降低]
affected_scope: [第3段, 后文两处回指]
status: suggested
~~~

删去一段不等于其作用已补回；移动段落不等于改变现实因果。高承载 U 可修改，但应看清它承担的事实、幽默、犹疑、铺垫等功能由谁接住。

## 3. 四种状态分开

| 状态 | 需要的依据 |
|---|---|
| suggested | 候选已提出 |
| accepted | 作者明确采用；不等于已改正文 |
| applied | 当前版本实际包含修改 |
| verified | 已执行指定范围的检查，记录结果与未查项 |

可另标 rejected / superseded；不以模型一句“已检查”代替核对，也不把编辑复查等同受众实测。

## 4. 对变更做回归，而非泛泛自评

只展开相关项：事实/来源、范围/情态/归属、D 的硬约束、高承载表达与角色声音、前后引用与回应、上一轮已修复问题及不改区域。口播改得准确后，也检查是否变得生硬；语感变自然后，也检查是否悄悄改变了事实。

有新因果或必然推论时，可寻找与材料相容的反例；没有找到反例不代表已证明等价，数量、归属和删去的限定仍须检查。比喻不按字面机械核验，但其人物归属与暗含事实不获豁免。具体做法见 [VOICE_TEXTURE](VOICE_TEXTURE.md)。

把候选放回受影响上下文；需要时读全文，记录未查范围。新的内容/结构候选不伪装成只改 U；具体材料、自由虚构和可公开范围按 METHOD 处理。

## 5. 多轮例子与停止

~~~text
v0：所有参与者都更快。
第1轮：材料仅支持12人的一次试验 → 在这次12人试验中更快。
第2轮：只压缩开头 → 保留这次试验的范围。
第3轮：加强语言 → 不能重新宣称普遍有效。
~~~

这是合成示例，见 [CASES](../tests/CASES.md)。定稿目标已满足、没有新的关键问题时停止；偏好分歧交作者取舍，探索请求则允许给具体备选。作者可依据现有材料、自己的朗读和有限反馈选稿，不必等完受众实验；效果证据的记录见 [METHOD](METHOD.md)。
