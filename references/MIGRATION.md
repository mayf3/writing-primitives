# 从七原语（V1.1）迁移到 vNext

**性质：概念迁移建议，不是已部署数据迁移。**旧提案保留自身版本身份；本目录没有更改任何旧文件、历史记录或分析器的存储合同。

## 一、映射

| 旧版 | vNext | 兼容注意 |
|---|---|---|
| D · Direction | D · Author Contract | 区分作者已确认与模型提出；observed 不覆盖 planned |
| C · ContentItem | C · ContentItem | 显式标明范围、情态、归属与来源 |
| E · Event | `C.kind=event` | 按需嵌套事件字段，保留 reality_mode 和 unknown |
| B · Beat | 按需 `Move` 视图 | 不再要求每段主认知跃迁；历史 B 编号可保留用于阅读旧评审 |
| U · Unit | U · Unit | 保留准确版本与原句锚点、说话人和高承载作用 |
| R · Relation | R · Relation | 只建有助于具体决策的边；收缩核心关系词表 |
| RS · ReaderStep | `Reader Evidence` 协议 | 区分假设、编辑推断、模型前缀预测、真人观察 |
| Evidence Cluster / High-load Unit | 派生分析 | 不升级成第 5/6 个核心对象 |
| 多轮修订记录 | 独立 Revision Protocol | suggestion / acceptance / application / verification 不可混同 |

## 二、历史审稿记录怎么读

- 旧版里的 `B.primary_reader_delta` 可作为作者或编辑**预期推进**保留；**不能机械转换为真人 RS 证据**。
- 旧版独立 E 可以转为一个 `C.kind=event`；如原来 E 指向多个 C，保留引用关系和来源信息，避免将多个意思压成一句。
- 旧版 RS 若标了 `listener_observed`，只有明确保留真实测试方法、受众范围与数据时才能迁为 `reader_observation`；否则降级为未核实记录。
- 旧 R 词表并不要求无损映射到少量新词；无法映射的关系保留自然语言注释，不虚构精确性。
- 旧版标记的 high-load U 依然是有价值的**保护候选**，并非在新版天然获得不许改的硬约束。
- 旧分析中“已经提出的改稿建议”不能当成“最新正文已落实”。检查稿件版本和状态。

## 三、工作流变化

旧默认：提取多类对象 → 划 B/RS → 找差异 → 改稿。

新默认：**确认作者约束与当前版本 → 寻找可举证的高影响问题 → 只为问题建最少对象 → 局部改 → 回归 → 停止。**

写作方向可以随作者选择变化，但必须记录“作者改变了约定”，不能事后悄悄修改。下一轮审稿默认只有 0–3 个主问题，而不是完整拆稿。其他意见归为可选实验或明确保留。

## 四、不做什么

- 不把 vNext 命名成已完成、已部署的稳定 2.0。
- 不自动覆盖旧的工作成果、PR 或数据模式。
- 不追求所有历史字段无损自动迁移。
- 不把旧实际人物案例复制到公开目录。
- 不把论文里的规律当成本系统的实验结果。

**验证标准：**若强普通提示词在同样成本下与 vNext 一样好，应该削减或放弃 IR 机制，而不是维护完整性。
